# MyAlpha 专属研究 Agent · 系统蓝图（设计文档 v1 · 2026-10-31）

来源：Owner 10/29 认可的蓝图方向（claude.ai 文档“MyAlpha 专属投资研究 Agent · 系统蓝图”）、GPT 10/29 修订，以及章程 CLAUDE.md 中“Why we collect”一节。本文档只描述设计，不改变任何程序行为。

## 1. 定位
- 通用大模型负责推理；系统的专有资产有四样：投资规则书、已验证经验库、错误记忆、考核体系。
- 不从头训练模型。微调只作为有条件的后期实验：需要数千条人工核验的标注，并且在冻结测试集上稳定胜过“通用大模型 + 检索 + 结构化规则”这一基线。
- 下单永远由 Owner 本人决定。

## 2. 五层数据流
| 层 | 内容 | 现有组件（举例） |
|---|---|---|
| 1 数据可信 | 来源、as_of、首次看到时间、哈希；缺失时写 unavailable | Daily / Guardian / QA、official_evidence、source store |
| 2 理解 | 结构化观点和命题，可追溯到原文 | wxc-bot claim_extractor、source_reading_memory |
| 3 判断 | 单一裁判（见第 4 节） | fo-1.0 前瞻账本、playbooks |

| 5 服务 | 首页四类结论 + 提醒 | 今日驾驶舱、Telegram |

## 3. 四个专有资产的数据契约
| 资产 | 记录单位 | 必备字段 | 状态 |
|---|---|---|---|
| 投资规则书 | 规则（带 ID 和版本） | 输入、条件、例外、缺数据时的行为、来源（Owner 决策编号） | OWN-SYS 草稿，等待 Owner 确认 |
| 经验库 | 规则家族 × 期限 × 环境 | 独立样本数（rfi-0.1）、命中、区间、环境覆盖 | 真实前瞻成熟样本为 0（首批 11/5） |
| 错误记忆 | 每条成熟结果一行 | fea-0.2 的主因 / 次因、证据、process_ok | 格式已冻结，尚未上线 |
| 考核体系 | 冻结测试集 + 前瞻记分卡 | 分母、区间、版本、哈希 | fsc-1.0 已上线；v4 测试集 11/1 抽样 |

## 4. 单一裁判
1. **先过确定性门槛：** 数据可信 → 硬风险 → 已有持仓风险 → 论点失效 → 正式规则触发。
2. **再排序：** 基本面 → 技术面 → 已验证方法 → 外部观点 → 媒体。
3. **输出四类：** 今日行动 / 观察 / 持有 / 暂不能判断。关键数据过期、缺失或冲突未解决时，输出“暂不能判断”；裁判自身出错时，也降级为“暂不能判断”，不给默认结论。
4. 未经验证的外部观点最多进入“观察”。每个结论都同时记录支持和反对的证据，以及当时的市场环境。

## 5. 证据阶梯（7 级，每一级都不能自动推出下一级）
收集 → 拆解 → 可检验 → 历史回测 → 影子观察 → 前瞻验证 → 可晋升（仍须 Owner 批准）。

## 6. 隐私边界
- 持仓、成本、金额和账户信息只放在私有账本，按账户分开存放，不进入公开的 docs/。
- Owner 对提醒的反馈（有用 / 没用 / 太吵）只存在私有区，并且只用来调整提醒的排序和频率。

## 8. 推进顺序（每一步看证据，不看日历）
1. **阶段 0（到 11/5）：** 稳住数据，11/5 首批真实成熟只做工程验收。
2. **阶段 1：** 错误归因和反馈记录上线；用冻结测试集验收抽取器；参数齐全的候选规则进入回放和影子观察。
3. **阶段 2：** 单一裁判上线，前台精简（以 8 个标准案例作为验收）；规则书 v1 由 Owner 逐条确认；核心 ETF 回撤分档提醒（Owner 10/30 已批准）。
4. **阶段 3：** 积累 60 日样本，形成可靠性趋势；是否晋升由 Owner 决定。
