# myAlphaView V3.3.0 手工数据治理升级

V3.3 将网站内所有主要手工数据统一为“新增、修改、取消、删除/停用、必要时撤回”的管理方式，并把期权持仓按券商账户分组展示。

## 期权持仓

- 按券商账户分组，每个账户显示浮盈、浮亏、净盈亏和报价覆盖数量。
- 顶部增加全账户期权盈亏汇总。Short 按 Ask、Long 按 Bid 估值；休市使用最近参考报价，无报价仓位不计入金额。
- 每笔开放持仓左侧提供“编辑”和“删除”。编辑用于修正手工录入；展期链仓位禁止直接改写。
- 删除需核对账户、合约、到期日与数量，并输入 `DELETE`；删除不进入历史。
- 主动平仓、到期作废或被行权误操作继续通过历史区“恢复持仓”撤回。

## 账户、正股与展期

- 正股覆盖计划按账户分组，支持新增、编辑、取消和删除；有关联开放期权时禁止删除。
- 券商账户支持新增、编辑、取消编辑、停用和恢复。有关联持仓时禁止停用，避免孤儿记录。
- 手工收盘 Delta 可以保存，也可以清除并恢复到自动/待确认状态。
- 展期历史增加“撤回展期”。仅当新仓仍为原始开放状态、没有继续展期或平仓时才能撤回；数据库事务会恢复旧仓、删除误建新仓和对应日志。

## 其它手工模块

- 个股策略价支持设置、修改和删除；删除后保留行情，但不再生成策略价触发信号。
- 核心资产预留预算增加“清除预算”；只删除资金配置，不修改既有 CORE_TIERS 阈值。

## 部署顺序

1. 将完整压缩包中的全部文件覆盖到 GitHub 仓库根目录并提交。
2. 在 Supabase SQL Editor 执行：
   `supabase/migrations/202609240002_crud_and_roll_undo.sql`
3. 运行 GitHub Actions 的 **Daily Dashboard Update**。
4. 浏览器强制刷新：Windows `Ctrl+F5`；Mac `Cmd+Shift+R`。

## 数据安全

- V3.3 不删除已有数据。
- 展期撤回由数据库事务完成，任何关联状态不一致都会拒绝执行。
- 账户使用停用/恢复代替永久删除。
- 永久删除只用于重复或错误录入的开放持仓及无关联正股计划。
